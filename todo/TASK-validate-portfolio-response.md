# TASK-validate-portfolio-response: Строгая валидация и ленивый итератор позиций GetPortfolio

## Проблема

`OperationsServiceComponent::getPortfolio()` и `GetPortfolioResponseMapper` превращают пустое HTTP-тело, отсутствие поля `positions`, `positions: null` или неверный тип в успешный пустой портфель, а маппинг всех позиций выполняется eagerly: ошибка маппинга второй позиции не даёт прочитать первую. Потребитель не может отличить корректный пустой портфель от дефекта API и теряет построчную семантику обработки.

## Требования

- [x] Пустое HTTP-тело завершается явным исключением.
- [x] Отсутствующее поле `positions` завершается явным исключением.
- [x] Поле `positions` неверного типа (null, строка, объект) завершается явным исключением.
- [x] `positions` обязан быть именно JSON-массивом: `{}` и объект с ключами — ошибка, пустой `[]` допустим.
- [x] Верхний уровень ответа — именно JSON-объект: top-level JSON-массив — ошибка.
- [x] Позиции маппятся лениво: DTO строится при итерации; ошибка маппинга одной позиции не скрывает предыдущие (`PortfolioDto::$positions` — итератор).
- [x] Элемент списка позиций не-объект — ошибка контракта (исключение при итерации).
- [x] Корректный пустой массив `positions: []` остаётся допустимым ответом (пустой итератор).
- [x] Ошибки JSON не маскируются.
- [x] Поведение покрыто unit-тестами без реального API (сырые HTTP/JSON-сценарии через MockHandler).
- [x] `composer stan` и `composer test` проходят.
- [x] `composer psalm` — только 4 преждесуществующие ошибки в `OrderbookCommand.php` / `OutputFormatTrait.php` (baseline не трогали; изменённые файлы чисты).
- [ ] `composer cs-check` — падает на отсутствующем сниффе `PrikotovCodingStandard...DtoStructureSniff` в vendor (преждесуществующее, вне диффа; baseline не трогали).

## Границы

- Не выполнять реальные T-Invest API-вызовы.
- Не менять сигнатуры публичных методов интерфейса; тип поля `PortfolioDto::$positions` изменён с `list` на `Iterator` (потребители пакета обновлены).
- Не трогать `getOperations()` — отдельный сценарий, выйдет своей задачей при необходимости.
- Не добавлять fallback, маскирующий ошибки ответа.
